# Project-Specific Standards

This file is the place for conventions that belong to a single project. The shared skill does not define them; add them when you adopt the skill in a project.

Status: placeholder. No project-specific rules are defined in this shared copy.

## Add here

- Libraries, frameworks, and internal APIs whose conventions differ from [`general-standards.md`](general-standards.md).
- Project-specific Ruff settings, per-file ignores, or compatibility notes, each with a reason.
- Naming, data modeling, testing, or documentation conventions that are local to the project.

## Boundary

- Keep project-specific rules local; do not weaken the shared Ruff configuration without documenting why.
- Do not infer a library's style from another project; read the official documentation for the installed version.
- When a project-specific rule differs from the shared standards, document it here; the project rule then applies to that project.
